# 私有原文检索

网页问答按问题从既有起朱楼资料库取原文和相邻段落。公开代码不包含整书、会员文字稿、私有 SQLite 数据库、向量文件或模型权重。`data/sources.json` 保留的是开发时精读得到的短转述和主题锚点，只作为内部路由与归属核验入口；实际回答依据始终重新从私有数据库读取。

## 配置与接口

服务端配置以下环境变量，不要写入前端或提交含私有路径的环境文件：

```sh
QIZHULOU_ROOT=/path/to/existing/qizhulou-mcp
QIZHULOU_DB=/path/to/private/index.sqlite
QIZHULOU_PYTHON=/path/to/existing/qizhulou-mcp/.venv/bin/python
QIZHULOU_RETRIEVAL_MODE=keyword
```

`QIZHULOU_DB` 默认是 ROOT 下的 `data/index.sqlite`。Python 优先顺序是调用参数 `python`、`QIZHULOU_PYTHON`、`PYTHON`、ROOT 下的 `.venv/bin/python`。使用既有项目安装好的 jieba、rank-bm25、NumPy 等依赖。不会自动下载模型、安装依赖、更新语料或重建索引。

```js
import { createRetriever } from "./lib/retrieval.mjs";
const retriever = createRetriever();
const status = retriever.status(); // 同步配置/已验证运行状态，不启动模型
const result = await retriever.search("明年要交首付，该怎么安排这笔钱？");
// result.sources: 最多4份原文上下文
// result.retrieval: mode / warning / coverage / elapsedMs
retriever.close(); // 在服务关闭时清理本服务创建的本地 worker
```

每个来源有稳定的段级 `id=docId:n`，并返回 `title/date/kind/docId/anchor/author/speaker/attribution/summary/text/publicUrl/evidenceLimitations`。`summary` 与 `text` 是同一份原文节选，最多1500个字符，并非生成摘要；命中段和邻段保留段号，必要时另附前方的说话人标签。`speaker` 只描述命中段，不能自动扩展到所有邻段。模型应引用返回的根 `id`，不能把正文里的任意邻段标识变成未提供的来源。

未配置、未找到相关来源、实时信息不在资料范围、模型/环境失败时都返回明确状态，不伪装成完整语料已检索成功。首次有效查询要在内存中初始化约六万段的关键词索引，后续复用一个持久 worker；最多排队4个请求，单批超时90秒，故障后可以重新启动。应用应显示首次加载状态。worker环境过滤密钥、令牌、密码、凭据及生成模型配置，保留HOME原值供本地缓存定位；检索子进程不持有生成模型凭据。

## 检索流程

关联正文和图片识别文本使用独立的 `reference` 来源。只有父帖属于已收录的公众号或知识星球、且作者或回答者已核实为大卫翁，关联资料才进入本语料范围。原作者与段落说话人分别保留；父帖的作者身份不会传给关联正文。`provenance.sourceRelations` 保留逐项核验的父帖关系，来源弹窗显示原资料、最多三个父帖链接和提取质量。

关联文章须有完整正文，图片 OCR 须完成原图复核，才进入应用答案支持片段。目录页、正文不完整或尚未复核的 OCR 仍可通过 MCP 定位，应用的候选检索、直接上下文和回答降级都执行相同质量门槛。

正式文字稿保留实际 `contentRole`、`edition`、`episodeDocId` 与 `episodePublishedAt`。同一期正式稿和 ASR 同时满足本次问题的命中条件时，优先正式稿；仅命中 ASR 时仍显示其真实版本。旧 ASR 段落可以直接回读，不同文字版本保留各自定位。来源日期与节目日期分别使用已记录的元数据。

1. SQLite 使用 `mode=ro` 与 `PRAGMA query_only=ON`，不调用原项目会写数据库的 `connect()`。
2. 在构建内存关键词索引前执行与 MCP `corpus=qizhulou` 一致的过滤：先筛选 book/wx/episode/transcript/zsxq，再核验关联 reference 的父文档。播客文档要求播客名明确为起朱楼，或符合既有旧版 ep/tr 数字编号。标题里出现起朱楼不算归属证明。
3. 复用原项目的分词、BM25 和 `get_context` 方法。ShowNotes、延伸书目与纯提问段不作为回答命中。当前原文库的变更应通过重启此独立服务重新加载；不在提问中触发全库重建。
4. 默认 `keyword` 为原问题 BM25、确定性的主题改写和已核主题锚点的组合。锚点只提供候选段号，正文必须现场从库中取出，不拿静态转述冒充原文。
5. 每次选取少量跨文档原文，应用主题及相关性门槛，去掉重复段落与同篇重复块。检索分数不是观点可信度或收益概率。没有可靠命中时返回空结果。
6. 问答以正文“回答者”区分提问人与答题者。普通文档只认冒号/换行的显式标签；仅3篇已逐段核对过且抽取时丢分隔符的对谈允许受限inline格式。沿标签回溯时保留标签位置；无法确认就留空并标“节目或资料中讨论”。“大卫翁的这本书……”这样的普通提及不会成为发言标签，发布者元数据也不会自动成为说话人。
7. 返回命中段加前后文；长段只截取与问题较相关的窗口，并标节选。只把本次少量片段交给模型，不上传完整书籍或数据库。

## 是否需要向量

本机已经有可复用的离线向量索引，因此无需再建一个。

2026-10-08 只读实测：起朱楼语料2784篇、60107段；SQLite 为76,230,656字节；现有 `vectors.npz` 为315,643,495字节（约301MiB），全索引123787向量块、122500唯一片段、512维。起朱楼60107段均有文本完全一致的向量，缺失0、过期0。排除不适合作为回答的片段后，56316个可检索片段也全部覆盖。

本地模型 `BAAI/bge-small-zh-v1.5` 可在 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 下加载；没有联网或下载权重。初次能力探针含模型冷启动约7.8秒，随后小候选查询39毫秒；这不是端到端问答延迟。

默认关键词模式不加载向量矩阵或编码模型，因此运行时 `coverage.indexed/stale` 为null，而不是假装本次已检查向量。需要比较时显式设置 `QIZHULOU_RETRIEVAL_MODE=hybrid`，它复用现有向量做候选融合，并校验片段文本是否与索引记录一致，过期向量不参与。模型缺失或失败会明确降级为关键词原文检索，不声称语义链路成功。

## 评估口径

开发校准集15问涉及首付、收入中断、职业集中、家庭现金流、问卷、黄金再平衡、处置效应、自由职业、还贷、货币基金、嘉宾归属、外币目标、锁定期，以及2个无可答来源问题。早期只加向量并未显著改善已核目标文档命中，加入精读主题入口才解决主要定位问题。

在同一批开发问题上，纯 BM25 命中预先列出的目标文档为8/15；关键词改写加核读锚点、以及在其上叠加向量，均为15/15。这是**开发集文档命中率，不是独立测试，也不是回答准确率**。曾发现命中文档却定位到不支持具体问题的段落，已据此修正段内选择；这更说明不能用文档命中替代逐段证据核验。

开发集复用进程的查询中位数约122毫秒（纯BM25）、210毫秒（关键词加锚点）、286毫秒（再加向量）。启动时词索引构建约11秒；包含全部方法及模型加载的单进程峰值约1.47GB。不同硬件、并发与语料版本会改变这些数值。生成模型耗时不在此表内。

另以未参与前述校准的5个自然表达做固定版本留出评估，最初有3题被过窄主题门槛误拒绝；两种检索模式都受影响。这些问题随后用于修复范围识别和回归，不能再称为独立测试。修复后，又检查5个新问法，仍发现“薪酬与自家公司股票的共同风险”可能只命中职业或分散的泛化段落，而未定位直接说明二者相关的段落。另针对核心现金流场景修正了收入主题抢占与锚点排序，最后实测“收入超过生活费，为何现金减少”已定位 `book-ch01:37`（支出、分期和现金流区别）及 `book-ch02:67`（快照与流水）。该题属于回归，不能据此声称所有复杂问法都已解决。相邻段及生成模型不能凭空补齐未检出的论据，应要求澄清或明确降级。

单独进程的资源对比：关键词模式峰值约654MB、首次有效查询约10.0秒、当时两次有效暖查询107/163毫秒；混合模式约1.47GB、首次有效查询约13.7秒，对应暖查询151/208毫秒。修复后的关键词回归5题暖查询约108–234毫秒。新的小样本没有显示足以抵消资源增长的稳定向量增益，也不能证明向量对其他问题无用。因此保留**关键词默认、现有向量显式可选**，不重建向量。私人问题、原文命中和逐题评语保存在项目工作区，不随代码公开。

## 测试与限制

`node --test test/retrieval.test.mjs` 可在不持有私人库的环境运行。合成 SQLite 夹具检查语料边界、显式说话人标签回溯、提问人不冒充回答者、提问中的私人资料不带入回答、原文长度及只读约束；另检查缺配置、无效输入及worker凭据隔离。4项测试通过。真实检索和真实模型验收必须另行运行，不能把合成测试通过当作生产链路成功。本次另实测Node→Python→原文库→来源结果链路成功，冷启动约10秒；应急金问题定位到 `tr-13:48` 并保留说话人未知，收益/安全/流动性问题定位到 `book-ch09:7`。生成模型验收由问答模块单独记录。

私有检索进程运行于本地单机，网站部署入口统一验证站点会话。库内语料共用一个检索范围，未按用户或单篇资料设置访问层级。部署应沿用已授权的语料范围；复制开源代码不会自动获得书籍、会员内容或本地索引的权利与访问权限。这里不提供当前行情、作者实时持仓、现行法规或最新产品合同核验。
